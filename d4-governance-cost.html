4.1–4.2 Governance, Administration & Cost D4 · 10%

อ่านประมาณ 35–45 นาที · objectives 4.1 (Pricing Model) และ 4.2 (Cost Management tools) — โดเมนเล็กแต่เก็บคะแนนง่าย

ตัวเลขราคาและโควตา Free Tier เปลี่ยนได้ตลอดเวลา — เว็บนี้ตั้งใจไม่ฝังตัวเลขเหล่านั้น ให้ลิงก์ไปหน้าทางการและติดป้าย "ตรวจสอบก่อนสอบ" เสมอ

Why it matters

Domain 4 มีแค่ ~4 ข้อ แต่เป็นข้อที่ "อ่านหนังสือ 30 นาทีก็ตอบได้" เพราะเป็นข้อเท็จจริงล้วน ๆ — อย่าปล่อยทิ้งโดเมนนี้เด็ดขาด

อุปมา
Governance & Cost เหมือนระบบบัตรเครดิตขององค์กร: Budget = วงเงินบัตร (เตือนเมื่อใกล้ถึง) · Cost Analysis = ดู statement ย้อนหลังแยกตามหมวด · Service Limits/Quotas = เพดานเครดิตที่ธนาคารกำหนด · Cloud Advisor = ที่ปรึกษาการเงินแนะว่า "ตรงไหนควรลด/เพิ่ม"

4.1 Pricing Model

Universal Credits และรูปแบบการจ่าย

  • Universal Credits — จ่ายล่วงหน้าเป็นเครดิต (annual commitment) แล้วนำไปใช้กับบริการใด ๆ ของ OCI ได้ทั้งหมด (ยกเว้นบางรายการ) — ได้ส่วนลดมากกว่า pay-as-you-go; หมดเครดิตแล้วยังใช้ต่อได้ (จ่ายตามจริง)
  • Pay As You Go (PAYG) — ไม่มี commitment จ่ายตามที่ใช้จริงรายเดือน เหมาะกับเริ่มต้น/ทดลอง
  • Free Tier — สองอย่างที่ต่างกันชัดเจน:
    • Always Free — ทรัพยากรที่ใช้ฟรีตลอดไป (เช่น VM Micro/A1 บางส่วน, object storage จำนวนหนึ่ง) ไม่มีวันหมดอายุของสิทธิ์
    • Trial credits — เครดิตทดลองใช้ฟรีชั่วคราว (30 วัน) สำหรับลองบริการทั้งหมด หมดอายุแล้วกลายเป็น PAYG
    รายละเอียดโควตา/ยอดเครดิต: ตรวจสอบก่อนสอบ
  • ราคาเท่ากันทุก region — OCI ไม่คิดราคาต่างกันตาม region (ต่างจาก cloud บางเจ้า) — เลือก region จาก latency/compliance ได้เต็มที่โดยไม่ต้องมองราคา

BYOL vs License Included

BYOL (Bring Your Own License)License Included
ใบอนุญาตใช้สิทธิ์ที่องค์กรซื้ออยู่แล้ว (เช่น Oracle Database EE, Windows Server) บน OCIOCI รวมสิทธิ์การใช้ software ไว้ในราคาแล้ว
ต้นทุนถูกลงถ้ามี license อยู่แล้ว (จ่ายแค่ infrastructure)แพงกว่าต่อหน่วย แต่ไม่ต้องมี license มาก่อน
เหมาะกับองค์กรที่มี Oracle Database EE อยู่แล้วเริ่มใหม่/ไม่มี license เดิม

Cost Estimator

OCI Pricing Calculator / Cost Estimator — เครื่องมือประมาณค่าใช้จ่ายก่อนสร้างทรัพยากร ใส่ service ที่จะใช้แล้วได้ราคารวมโดยประมาณ (ไม่ต้อง login) ใช้ก่อนเสนอราคา/ออกแบบสถาปัตยกรรม

SLA และ Support Plans

  • SLA (Service Level Agreement) — OCI ประกาศ SLA เป็น 3 แกนหลัก:
    • Availability SLA — % uptime ต่อเดือนของแต่ละบริการ (เช่น 99.9% / 99.95%)
    • Manageability SLA — การตอบสนองต่อการขอ service request ตาม severity
    • Performance SLA — ตัวชี้วัด performance บางบริการ
    ตัวเลข SLA เป๊ะ ๆ ของแต่ละบริการ: ตรวจสอบก่อนสอบ
  • Support plans — ขั้นสนับสนุนหลายระดับ (เช่น Basic/Developer/Proactive Containment — ชื่อและ SLA เปลี่ยนได้) ตั้งแต่ Community/Basic ที่รวมในราคา ไปจนถึง enterprise support แบบมี TAM และ response ตาม severity; เลือกตามความสำคัญของ workload

เครื่องมือบริหารจัดการ (หลายทางเลือก ใช้ได้ทั้งหมด)

เครื่องมือใช้เมื่อไร
ConsoleUI บนเว็บ — ทำทุกอย่างแบบคลิก; เหมาะกับเริ่มต้น/งานไม่บ่อย
Cloud Shellterminal บนเบราว์เซอร์ (เครื่อง OCI ให้ฟรี) มี OCI CLI พร้อม ไม่ต้องติดตั้งบนเครื่องตัวเอง
OCI CLIcommand line — อัตโนมัติ/scripting
SDKsJava/Python/Go/.NET/TypeScript/Ruby — เขียนแอปเรียก OCI API

4.2 Budgets และ Alert Rules

  • Budget — กำหนดงบประมาณ (รายเดือน/รายไตรมาส/รายปี, แบบ recurring หรือ custom period) ผูกกับ compartment หรือ cost-tracking tag (อยากแยกตามทีม/โปรเจกต์)
  • Budget alert rules — ส่ง notification (ผ่าน Notifications topic) เมื่อค่าใช้จ่ายจริงหรือค่าพยากรณ์ (forecast) ผ่าน threshold ที่ตั้ง (เช่น 50%, 80%, 100%) — Budget ไม่ตัดการใช้งาน แค่เตือน
  • Budget เป็น composite tracking: ผูกได้หนึ่ง compartment หรือหนึ่ง tag ต่อ budget — วางแผน compartment/tag ให้ดี

Cost Analysis และ Cost/Usage Reports

  • Cost Analysis — กราฟ/ตารางค่าใช้จ่ายย้อนหลัง แยกตาม service, compartment, region, tag — ตอบ "เงินเดือนนี้หายไปกับอะไร"
  • Cost Reports — รายงานละเอียด (CSV) ระดับ line item (แต่ละทรัพยากร แต่ละชั่วโมง) ส่งเข้า Object Storage bucket อัตโนมัติ — ใช้กับระบบภายใน/BI tools
  • Usage Reports — ข้อมูล utilization (ทรัพยากรกี่ชั่วโมง) แบบดิบ สำหรับวิเคราะห์/chargeback
  • Cost-tracking tags — tags ที่กำหนดให้ใช้หั่นต้นทุน (เช่น CostCenter=Finance); tag defaults ทำให้ทรัพยากรใหม่ติด tag อัตโนมัติตอนสร้าง

Quotas vs Service Limits vs Budgets — สรุปความต่าง

Service LimitsQuotasBudgets
คืออะไรเพดานจำนวนทรัพยากรที่ tenancy ใช้ได้ต่อ region (เช่น จำนวน VCN, shape A1 core)เพดาน ที่คุณกำหนดเอง สำหรับ compartment (เข้มกว่า service limit)เพดาน ค่าใช้จ่ายเงิน
ใครกำหนดOracle (per region/tenancy, ขอเพิ่มได้)คุณ (ผ่าน Console/CLI)คุณ
ขอบเขตregion + tenancycompartment (child ไม่เกิน parent)compartment หรือ cost-tracking tag
ผลเมื่อเกินสร้างทรัพยากรไม่ได้สร้างทรัพยากรไม่ได้ (เกิน quota)ไม่บล็อก — แจ้งเตือนอย่างเดียว
ใช้ทำอะไรกัน resource exhaustion เริ่มต้นควบคุมการใช้ต่อทีม/โครงการ (governance)ควบคุมการเงิน
จุดสับสนคลาสสิก
"อยากให้สร้างเกิน X ตัวไม่ได้" → Quota (หรือ service limit ถ้าเป็นเพดานรวม) · "อยากให้หยุดใช้เมื่อครบงบ" → Budget — แต่ Budget ไม่หยุดจริง แค่เตือน! การหยุดจริงต้องพึ่ง automation (Events+Functions) หรือ quotas
Service limits ขอเพิ่มผ่าน Help → Support → Request service limit increase (เลือก category/resource/limit)

Cloud Advisor

  • Cloud Advisor — บริการที่ปรึกษาอัตโนมัติ วิเคราะห์การใช้งานแล้วให้คำแนะนำใน 4 แกนหลัก: Cost, Security, Performance, Availability (และบางครั้ง operational excellence)
  • ตัวอย่าง: "instance นี้ CPU ต่ำผิดปกติ — พิจารณาลด size" · "bucket นี้ public — พิจารณาปิด" · "volume นี้ไม่มี backup — พิจารณาเปิด"
  • ใช้ร่วมกับ budgets/cost analysis เป็นวงจร governance: มอนิเตอร์ → วิเคราะห์ → แก้ → วัดผล

การออกแบบ Compartment เพื่อแยกต้นทุน

  • แยก compartment ตาม ทีม/โปรเจกต์/สภาพแวดล้อม (เช่น Production/Web, Production/DB, Dev/Sandbox) — ได้ทั้ง cost report แยกและ policy แยก
  • อย่าซ้อนลึกเกินไป — 3–4 ชั้นพอ; โครงสร้าง root → environment → service/project
  • ใช้ cost-tracking tags สำหรับมิติที่ compartment ให้ไม่ได้ (เช่น cost center ข้าม project)
  • quotas ตั้งบน compartment ป้องกันทีมหนึ่งใช้ทรัพยากรจนหมดทั้ง tenancy

Exam Focus

ข้อสอบชอบถาม
  • Free Tier มี 2 แบบ: Always Free (ถาวร) vs trial credits (ชั่วคราว) — อย่าสับสน
  • ราคา OCI เท่ากันทุก region
  • อยากประมาณราคาก่อนสร้าง → Cost Estimator; ดูย้อนหลังว่าใช้ไปเท่าไร → Cost Analysis; รายงาน line-item → Cost Reports
  • งบเกินแล้ว Budget ไม่ตัดบริการ — แค่เตือน
  • อยาก บล็อก ไม่ให้สร้างเกินกำหนด → Quotas / Service Limits
  • BYOL = มี license อยู่แล้ว; License Included = ทุกอย่างในราคาเดียว
  • Cloud Advisor แนะในแกน Cost/Security/Performance/Availability

Common Traps

กับดัก
  • "Budget ตัดการใช้งานเมื่อครบวงเงิน" — ผิด: แจ้งเตือนเท่านั้น ทรัพยากรยังรันและยังถูกคิดเงิน
  • "Free Tier trial 30 วัน = Always Free" — ไม่: trial หมดแล้วเป็น PAYG; Always Free ใช้ได้ตลอด (โควตาจำกัด)
  • "Region ถูกกว่า region อื่น" — ผิด: OCI ตั้งราคาเท่ากันทุก region
  • "Quota = Budget" — Quota จำกัดจำนวนทรัพยากร (บล็อกการสร้าง); Budget จำกัดเงิน (เตือนอย่างเดียว)
  • "cost-tracking tag ไม่ต้อง unique" — ควรมีมาตรฐานเดียวทั้งองค์กร ไม่งั้นรายงานหั่นไม่ได้
  • "Service limit ขอเพิ่มที่ Oracle ไม่ได้" — ขอได้ผ่าน support request โดยระบุ category/resource

Scenario

Scenario 1
ผู้จัดการอยากรู้ว่า compute/DB/storage ทีมไหนกินเงินเท่าไร และอยากให้เตือนเมื่อทีม Finance ใช้เกิน 80% ของงบ 50,000 บาท/เดือน ทำอย่างไร?
วิธีคิด: (1) ติด cost-tracking tag CostCenter=Finance ให้ทรัพยากรของทีม (หรือแยก compartment) (2) สร้าง Budget ผูกกับ tag/compartment นั้น (3) ตั้ง alert rule 80% (และ 100%) ส่งผ่าน Notifications — ตอบได้ทั้ง "ดู" และ "เตือน"
Scenario 2
ทีม sandbox ชอบสร้าง VM จำนวนมากจนเกินกำหนด ผู้บริหารต้องการให้ "สร้างไม่ได้เลยเมื่อครบ 10 instances" — ใช้อะไร?
วิธีคิด: คีย์ = บล็อกการสร้าง → Quota บน compartment sandbox (เช่น จำกัด instance count = 10) — Budget ไม่ตอบโจทย์เพราะแค่เตือน

Check yourself

ไม่มีอะไรถูกปิด — Budget แจ้งเตือนอย่างเดียว (ผ่าน Notifications) ทรัพยากรยังทำงานและถูกคิดเงินต่อ
Always Free = สิทธิ์ถาวรสำหรับทรัพยากรชุดหนึ่ง; Trial = เครดิตทดลองชั่วคราว (ปกติ 30 วัน) สำหรับใช้บริการทั้งหมด แล้วกลายเป็น PAYG
Cost Reports (CSV ระดับ line item ส่งลง Object Storage bucket) — Cost Analysis ดูภาพรวม/กราฟ ไม่ละเอียดเท่ารายงานนี้
Oracle กำหนด Service Limits (เพดาน tenancy ต่อ region, ขอเพิ่มได้); คุณกำหนด Quotas เอง (เพดาน compartment ของคุณ)
องค์กรที่มี license Oracle อยู่แล้ว (เช่น Database EE) — นำมาใช้บน OCI จ่ายแค่ infrastructure ถูกลง; ถ้าไม่มี license เลือก License Included
