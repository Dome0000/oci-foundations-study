Quick Reference

⚡ OCI Foundations 2026 - Quick Sheet สรุปด่วนกระชับ 2 หน้า

เน้นอ่านทวนก่อนเข้าห้องสอบ

🌐 Global Infrastructure Domain 1

  • Region: พื้นที่ทางภูมิศาสตร์ที่ตั้ง Data Center แบ่งเป็น Multi-AD หรือ Single-AD
  • Availability Domain (AD): Data Center 1 แห่งหรือมากกว่า มีระบบไฟ ความเย็น เครือข่ายแยกอิสระ ไม่แชร์จุดพัง (Faults) ร่วมกัน
  • Fault Domain (FD): กลุ่ม Hardware / Rack / Power Switch ภายใน AD เดียวกัน แต่ละ AD มี 3 FDs เสมอ
  • ทำไมต้องมี FD: ป้องกัน Hardware Failure เฉพาะจุด และป้องกันไม่ให้ Maintenance กระทบเครื่องทั้งหมดพร้อมกัน (Anti-affinity)
  • Realm: กลุ่ม Regions ที่แยกกันเด็ดขาด (Commercial, Government, Sovereign) ไม่แชร์ข้อมูลหรือบัญชีกัน

📁 Tenancy & Compartment Domain 1

  • Tenancy: บัญชีคลาวด์ระดับบนสุด (Root Compartment) เมื่อเปิดใช้งาน OCI
  • Compartment: หน่วยจัดกลุ่มทรัพยากรเชิงตรรกะ (Logical Boundary)
  • คุณสมบัติสำคัญ: ซ้อนกันได้สูงสุด 6 ระดับ, ข้าม Region ได้ (Global Scope), ทรัพยากรย้ายข้าม Compartment ได้
  • ไม่ใช่: ไม่ใช่เครือข่าย ไม่ใช่ Firewall และไม่ใช่ Physical Data Center
  • วัตถุประสงค์: ควบคุมสิทธิ์ (Policy Boundary), แบ่งบิล (Cost Tracking), และจำกัดโควตา (Quotas)

🔀 VCN Gateways Cheat Sheet Domain 2

  • Internet Gateway (IGW): เข้า-ออก Internet ได้ 2 ทิศทาง สำหรับ Public Subnet
  • NAT Gateway: ออก Internet ทางเดียว (Outbound only) เพื่อ Update Patch ไม่ให้ภายนอกยิงเข้ามา สำหรับ Private Subnet
  • Service Gateway (SGW): เชื่อมต่อ Private Subnet ไปยัง OCI Public Services (เช่น Object Storage, Autonomous DB) ผ่าน Oracle Network ไม่ผ่าน Internet
  • Dynamic Routing Gateway (DRG): เสมือน Virtual Router เชื่อม VCN ไปยัง On-premises (Site-to-Site VPN, FastConnect) หรือเชื่อมข้าม VCN (Peering)
  • LPG (Local Peering Gateway): เชื่อม 2 VCN ใน Region เดียวกันโดยตรง

🛡️ Security List vs NSG Domain 2

  • Security List (SL): บังคับใช้ระดับ Subnet ทุก Instance ใน Subnet นั้นต้องรับกฎเดียวกันทั้งหมด
  • Network Security Group (NSG): บังคับใช้ระดับ VNIC / Instance เจาะจงเฉพาะเครื่องได้
  • Stateful vs Stateless: Default เป็น Stateful (ขาไปเปิด ขากลับเปิดให้อัตโนมัติไม่ต้องเขียนกฎ)
  • ข้อสอบชอบถาม: ต้องการคุมความปลอดภัยเครื่องที่อยู่ใน Subnet เดียวกันแต่ใช้กฎต่างกัน → ตอบ NSG

💾 Storage Decision Guide Domain 2

  • Block Volume: ต่อกับ Compute เป็นดิสก์ข้อมูล/OS (Boot Volume), NVMe SSD ประสิทธิภาพสูง, ติดตั้ง Database
  • File Storage (FSS): Shared File System มาตรฐาน NFS v3 (POSIX) แชร์ให้เครื่องหลายพันเครื่องอ่านเขียนพร้อมกัน
  • Object Storage: เก็บไฟล์ภาพ วิดีโอ ก้อนข้อมูล Unstructured ผ่าน HTTP REST API, ไม่จำกัดขนาด, ทำ Pre-Authenticated Requests (PAR) ได้
  • Archive Tier: เก็บข้อมูลระยะยาว ต้นทุนต่ำสุด ต้อง Restore (หลายชั่วโมง) ก่อนดาวน์โหลดได้

🗄️ Database Quick Reference Domain 2

  • Autonomous Database (ADB): ดูแลตัวเองอัตโนมัติ (Self-driving, Self-securing, Self-repairing) มี ATP (OLTP), ADW (Analytics)
  • Base Database Service: จัดการผ่าน Console แต่ผู้ใช้ยังได้ Root Access / OS Access
  • Exadata Database Service: ประสิทธิภาพสูงสุดระดับ Enterprise บนฮาร์ดแวร์ Exadata
  • MySQL HeatWave: รัน OLTP + OLAP (In-Memory Engine) จบในฐานข้อมูลตัวเดียว

🔐 IAM Policy Syntax & Verbs Domain 3

  • ไวยากรณ์: Allow <subject> to <verb> <resource> in <location>
  • ลำดับสิทธิ์ (น้อย → มาก):
    inspect (ดูรายชื่อ) < read (ดูรายละเอียดและเนื้อหา) < use (ใช้งานอัปเดต แต่สร้าง/ลบไม่ได้) < manage (สิทธิ์เต็ม Admin สร้าง-ลบได้)
  • Dynamic Group: ให้สิทธิ์ Compute Instance รัน API โดยใช้ Instance Principals ไม่ต้องฝัง Key ในโค้ด

📊 Budgets vs Quotas vs Service Limits Domain 4

  • Budgets: ตั้งแจ้งเตือนค่าใช้จ่าย (Alert) ผ่าน Email/Slack ไม่มีวันหยุดหรือสั่งปิดเครื่องเด็ดขาด!
  • Compartment Quotas: ผู้ดูแลระบบกำหนด policy ล็อกไม่ให้สร้าง Resource เกินโควตาใน Compartment
  • Service Limits: ขีดจำกัดสูงสุดเริ่มต้นที่ Oracle ตั้งไว้ให้กับ Tenancy (ขอเพิ่มได้โดยส่ง Support Request)
  • Triple SLA: การันตี 3 ด้าน: Availability (ความพร้อมใช้), Manageability (การจัดการผ่าน API), Performance (ประสิทธิภาพเครือข่าย)
Domain 1 (35-40%)

1. Getting Started with OCI

▶ 1.1 Cloud Fundamentals, Deployment Models & Access Methods

ระบบคลาวด์คอมพิวติงของ OCI นำเสนอการทำงานบนสถาปัตยกรรม Gen 2 Cloud ที่เน้นประสิทธิภาพ ความปลอดภัยแบบ Security-First และความยืดหยุ่นในการจัดวางโครงสร้างระบบ

IaaS (Infrastructure as a Service)

เช่าโครงสร้างพื้นฐานระดับฮาร์ดแวร์ เช่น Compute VM, Bare Metal, Storage, Virtual Cloud Network โดยผู้ใช้รับผิดชอบ OS และแอปพลิเคชัน

Exam Keyword: Full OS control, Manage your own VM, Raw infrastructure
PaaS (Platform as a Service)

คลาวด์ดูแลฮาร์ดแวร์ OS แพตช์อัตโนมัติ ผู้ใช้พัฒนาและวางแอปพลิเคชัน/ข้อมูล เช่น Autonomous Database, OKE, OCI Functions

Exam Keyword: Managed platform, Focus on code/data, Auto-patching OS
SaaS (Software as a Service)

โปรแกรมสำเร็จรูปพร้อมใช้งานผ่านเว็บเบราว์เซอร์ ผู้ให้บริการจัดการทั้งหมด เช่น Oracle Fusion Cloud ERP, HCM, NetSuite

Exam Keyword: End-user application, Fully managed software
Elasticity & Scalability

Elasticity: ปรับขยายและลดขนาดทรัพยากรตามโหลดแบบอัตโนมัติ | Scalability: ขยายขนาดได้ทั้งแนวตั้ง (Scale-up) และแนวนอน (Scale-out)

Exam Keyword: Grow and shrink dynamically, Pay only for what you use
OCI Dedicated Region

ยกบริการ OCI Cloud แบบเต็มรูปแบบทุกบริการไปติดตั้งไว้ใน Data Center ของลูกค้าเอง ตอบโจทย์ Data Sovereignty สูงสุด

Exam Keyword: All OCI services in customer data center, Strict compliance
Oracle Alloy

แพลตฟอร์มที่เปิดให้พันธมิตร (Partners/Service Providers) นำโครงสร้างพื้นฐาน OCI ไปรีแบรนด์และเปิดให้บริการคลาวด์ในนามของตนเอง

Exam Keyword: Partner-operated cloud, White-label cloud provider

ตารางเปรียบเทียบ: OCI Deployment Options

รูปแบบ (Model) สถานที่ติดตั้ง (Location) บริการที่ได้รับ (Services Available) กลุ่มเป้าหมายข้อสอบ (Key Target)
Public Cloud Oracle Global Data Centers ทั่วโลก ครบทุกบริการของ OCI องค์กรทั่วไปต้องการความยืดหยุ่น จ่ายตามจริง
Dedicated Region Data Center ของลูกค้าเอง ครบทุกบริการเหมือน Public Cloud องค์กรที่ต้องการ Data Residency 100% ภายในประเทศ
Cloud@Customer Data Center ของลูกค้า เฉพาะบริการ Exadata หรือ Compute งานฐานข้อมูลหนักที่ต้องอยู่ใกล้ On-premises Core System
Multicloud (OD@Azure/Google/AWS) ติดตั้งใน Data Center พันธมิตร Oracle Database Services แอปอยู่บน Azure/GCP/AWS ต่อ Database ออราเคิลแบบ Low-latency

ช่องทางการเข้าถึง OCI (Access Methods)

สามารถบริหารจัดการทรัพยากร OCI ได้ผ่าน 5 ช่องทางหลัก:

  • OCI Console: เว็บ Graphical User Interface (GUI) ใช้งานง่ายผ่านเบราว์เซอร์
  • OCI Command Line Interface (CLI): คำสั่ง command-line ทำงานบน Shell เหมาะกับ automation scripts
  • Software Development Kits (SDKs): ไลบรารีสำหรับนักพัฒนา (รองรับ Java, Python, TypeScript/JS, Go, .NET, Ruby)
  • REST APIs: เรียกใช้งานผ่าน HTTP Requests มาตรฐาน (ต้องลงนามคำขอด้วย API Signing Key)
  • Cloud Shell: เบราว์เซอร์เทอร์มินัล Linux ฟรี มี OCI CLI และเครื่องมือ Dev ติดตั้งพร้อมใช้งานทันที และมีที่เก็บไฟล์ส่วนตัว ตรวจสอบกับเอกสารล่าสุด
  • Terraform / Resource Manager: บริหารจัดการ Infrastructure as Code (IaC) ผ่าน OCI Resource Manager แบบ Managed Service
💡 Exam Tip: Free Tier & Always Free
OCI มีบริการ Always Free Services ที่ใช้งานได้ฟรีตลอดชีพไม่มีวันหมดอายุ (เช่น Autonomous Database ฟรี, Compute shapes บางรุ่น, Object Storage) และมี Free Trial Credits ที่มีอายุจำกัด ตรวจสอบกับเอกสารล่าสุด (เมื่อยอดเงินเครดิตทดลองหมด ทรัพยากร Always Free จะยังคงใช้งานได้ต่อเนื่องโดยไม่ถูกตัดเงินอัตโนมัติ)
▶ 1.2 OCI Global Infrastructure Architecture (Realm, Region, AD, FD)

สถาปัตยกรรมโครงสร้างพื้นฐานระดับสากลของ OCI ออกแบบลำดับชั้นแบบ Realm → Region → Availability Domain (AD) → Fault Domain (FD) เพื่อรับประกัน High Availability (HA) และ Disaster Recovery (DR)

ภาพจำลองสถาปัตยกรรม Region > Availability Domain (AD) > Fault Domain (FD) โดย 1 AD มี 3 FDs เสมอ

ตารางเปรียบเทียบข้อสอบออกบ่อย: Availability Domain vs Fault Domain

คุณลักษณะ (Feature) Availability Domain (AD) Fault Domain (FD)
นิยามทางกายภาพ ศูนย์ข้อมูล (Data Center) แยกอิสระจากกัน กลุ่มฮาร์ดแวร์ / Rack / สวิตช์เครือข่าย ภายใน AD เดียวกัน
จำนวนต่อ AD แต่ละ Region มี 1 หรือ 3 ADs แต่ละ AD มี 3 Fault Domains เสมอ
ป้องกันความเสี่ยงระดับใด ป้องกันภัยพิบัติระดับตึก Data Center (ไฟดับน้ำท่วมตึก) ป้องกันตู้ Rack ดับ, สวิตช์พัง, หรือการบำรุงรักษาฮาร์ดแวร์
ความล่าช้าเครือข่าย (Latency) ต่ำมาก (เชื่อมด้วยไฟเบอร์ใยแก้วความเร็วสูง) ต่ำที่สุด (อยู่ในดาต้าเซ็นเตอร์ห้องเดียวกัน)
Exam Keyword ที่ชี้มา "Separate data center", "Disaster recovery in region" "Anti-affinity", "Hardware failure within AD", "Unexpected hardware failure"
⚠️ Exam Trap: ข้อสอบหลอกเรื่อง Single-AD Region
อย่าเข้าใจผิดว่า Region ที่มีแค่ 1 Availability Domain จะทำ High Availability (HA) ไม่ได้! เพราะภายใน 1 AD จะมี 3 Fault Domains เสมอ ทำให้เราสามารถกระจาย VM 2 ตัวไปอยู่คนละ Fault Domain (เช่น FD 1 และ FD 2) เพื่อรับประกันความพร้อมใช้งานเมื่อเกิดปัญหาฮาร์ดแวร์ได้
▶ 1.3 Tenancy, Compartments & Resource Organization

Compartment คือหัวใจสำคัญของการบริหารจัดการบน OCI เป็นหน่วยจัดกลุ่มเชิงตรรกะที่แยกทรัพยากรออกจากกันอย่างเป็นระบบ

โครงสร้างลำดับชั้น Tenancy > Compartment พร้อมตัวอย่างการสโคป Policy สิทธิ์การจัดการเครือข่าย
Global Scope

Compartment เป็นทรัพยากรระดับสากล ไม่ขึ้นกับ Region ทรัพยากรที่อยู่ใน Compartment เดียวกันสามารถกระจายอยู่คนละประเทศหรือคนละทวีปได้

Exam Keyword: Global logical entity, Span multiple regions
Nesting (ซ้อนกันได้ 6 ระดับ)

สามารถสร้าง Sub-compartment ซ้อนกันได้ลึกสูงสุด 6 ระดับ เพื่อสะท้อนโครงสร้างองค์กร หรือแผนกงานย่อย

Exam Keyword: Up to six levels deep, Hierarchical structure
Resource Movement

สามารถย้ายทรัพยากร (เช่น VM, VCN, Block Volume) จาก Compartment หนึ่งไปยังอีก Compartment หนึ่งได้โดยไม่ต้องลบสร้างใหม่

Exam Keyword: Move resources between compartments without downtime
🎯 Exam Keyword: ถามหา "Logical Boundary" ให้ตอบ Compartment เสมอ!
ถ้าโจทย์ถามถึง "Logical collection of related resources" หรือ "Isolate resources for access control and billing" คำตอบที่ถูกต้องคือ Compartment (ไม่ใช่ VCN เพราะ VCN คือ Network Boundary ไม่ใช่ Resource Boundary)
Domain 2 (30-35%)

2. Core OCI Services

▶ 2.1 Compute, Containers & Serverless (VM, Bare Metal, OKE, Functions)
Bare Metal Compute

ได้สิทธิ์ควบคุมเซิร์ฟเวอร์กายภาพ 100% ตัวเดียวทั้งเครื่อง ไม่มี Hypervisor ของคลาวด์มาคั่น ประสิทธิภาพสูงสุด ปราศจาก Noisy Neighbors

Exam Keyword: Direct hardware access, No hypervisor, Single-tenant isolation
Virtual Machine (VM)

รันอยู่บน Hypervisor แชร์เครื่องกายภาพร่วมกับผู้อื่น (Multi-tenant) หรือเป็น Dedicated Host เหมาะกับเวิร์กโหลดทั่วไปที่ต้องการความยืดหยุ่น

Exam Keyword: Hypervisor-based, Cost-effective, General workloads
Flexible Shapes

สามารถเลือกจำนวน OCPU และขนาดหน่วยความจำ (RAM) ได้อย่างอิสระตามความต้องการจริง โดยไม่ต้องยึดติดกับอัตราส่วนสเปกตายตัว

Exam Keyword: Customize exact OCPUs and memory, Avoid overprovisioning
Instance Pools & Autoscaling

กลุ่มของ Compute Instance ที่สร้างจากแม่แบบเดียวกัน (Instance Configuration) ขยายหรือลดจำนวนอัตโนมัติตาม Metric (CPU/Memory) หรือตามเวลา (Schedule)

Exam Keyword: Metric-based scaling, Schedule-based scaling, Instance configuration
OKE (Container Engine for Kubernetes)

บริการจัดการ Kubernetes Cluster แบบ Fully-managed โดย Oracle ดูแล Master Node ให้ฟรี ผู้ใช้จ่ายเฉพาะ Worker Nodes

Exam Keyword: Managed Kubernetes, Container orchestration, Free control plane
OCI Functions

Serverless Compute รันโค้ดตอบสนองต่อ Event สร้างบนมาตรฐานโอเพนซอร์ส Fn Project จ่ายเงินเฉพาะช่วงวินาทีที่โค้ดประมวลผลจริงเท่านั้น

Exam Keyword: Event-driven, Serverless execution, Fn Project, Pay per execution time
Container Instances

รัน Container โดยตรงบน OCI ทันทีโดยไม่ต้องสร้างเซิร์ฟเวอร์ VM และไม่ต้องจัดการ Kubernetes Cluster

Exam Keyword: Run containers instantly, No VM management, No Kubernetes overhead
▶ 2.2 Networking & Gateways Architecture (VCN, Subnets, IGW, NAT, SGW, DRG)

Virtual Cloud Network (VCN) คือเครือข่ายส่วนตัวเสมือนที่สร้างขึ้นบน OCI ใน Region หนึ่งๆ ประกอบด้วย Subnets, Route Tables, Security Lists/NSGs และเกตเวย์ประเภทต่างๆ

ผังแสดงการทำงานของ VCN พร้อม Public/Private Subnets และ 4 เกตเวย์หลักที่ข้อสอบออกบ่อย

ตารางเปรียบเทียบหมวดเกตเวย์ (ออกข้อสอบแน่นอน 2-3 ข้อ)

เกตเวย์ (Gateway) ทิศทางการรับส่งข้อมูล ใช้สำหรับ Subnet ใด Exam Keyword / กรณีใช้งานข้อสอบ
Internet Gateway (IGW) 2 ทิศทาง (Inbound & Outbound) Public Subnet เท่านั้น เว็บเซิร์ฟเวอร์ที่ต้องการให้คนทั่วไปบนโลกอินเทอร์เน็ตเข้าถึงได้
NAT Gateway 1 ทิศทาง ขาออกเท่านั้น (Outbound-only) Private Subnet เครื่อง Database ต้องการโหลด OS patch หรืออัปเดตซอฟต์แวร์โดยไม่ให้ภายนอกยิงเข้ามา
Service Gateway (SGW) วิ่งภายใน Oracle Private Network (ไม่แตะเน็ต) Private หรือ Public Subnet เชื่อมต่อไปยัง Object Storage หรือ Autonomous DB โดยไม่ต้องผ่าน Public Internet
Dynamic Routing Gateway (DRG) 2 ทิศทาง ระหว่าง VCN กับภายนอก ทุก Subnet เชื่อมต่อไป On-premises ด้วย Site-to-Site VPN หรือ FastConnect หรือเชื่อมข้าม VCN Peering
⚖️ Load Balancer (L7) vs Network Load Balancer (L4)
  • Flexible Load Balancer (Layer 7): รองรับ HTTP/HTTPS, ทำ SSL Termination, Path-based routing, ปรับ Bandwidth ได้ยืดหยุ่น
  • Network Load Balancer (Layer 4): รองรับ TCP/UDP, ทำงานแบบ Pass-through, Ultra-low latency, ความเร็วสูงระดับไมโครวินาที
⚖️ FastConnect vs Site-to-Site VPN
  • Site-to-Site VPN (IPSec): วิ่งผ่าน Public Internet เข้ารหัสเป็นอุโมงค์ VPN ต้นทุนประหยัด ติดตั้งง่าย
  • FastConnect: ลากสายเคเบิลตรง Dedicated Private Connection ไม่ผ่าน Internet แบนด์วิดท์สูง เสถียรที่สุด ปลอดภัยสูงสุด
▶ 2.3 Storage Services Deep Dive & Decision Matrix
Block Volume

จัดเก็บข้อมูลระดับบล็อกบน NVMe SSD ติดตั้งเข้ากับ VM โดยตรง (Boot Volume หรือ Data Disk) ปรับความเร็วได้ (Ultra High, Higher, Balanced, Lower Cost)

Exam Keyword: SAN storage, NVMe SSD, OS boot drive, High IOPS
File Storage (FSS)

บริการแชร์ไฟล์แบบเครือข่าย รองรับโปรโตคอล NFS v3 มาตรฐาน POSIX สามารถ Mount ใช้งานพร้อมกันได้หลายพันเครื่อง

Exam Keyword: Shared file system, NFS v3, POSIX-compliant, Shared across VMs
Object Storage

จัดเก็บข้อมูลไม่มีโครงสร้าง (Unstructured Data) ไฟล์ขนาดใหญ่ วิดีโอ ก้อนแบ็กอัป เข้าถึงผ่าน HTTP/HTTPS REST API หรือ S3-compatible API

Exam Keyword: Buckets, HTTP API, Unstructured data, Infinite scaling
Pre-Authenticated Request (PAR)

สร้าง URL พิเศษชั่วคราวให้ผู้อื่นดาวน์โหลดหรืออัปโหลดไฟล์ใน Object Storage ได้ โดยไม่ต้องมีบัญชี OCI หรือผ่านการล็อกอิน กำหนดเวลาหมดอายุได้

Exam Keyword: Temporary access URL, No OCI credentials needed, Expiring link

ตารางตัดสินใจเลือกพื้นที่จัดเก็บข้อมูล (Storage Decision Table)

บริการ (Service) รูปแบบข้อมูล (Type) โปรโตคอล / การเข้าถึง การแชร์ข้ามเครื่อง เคสการใช้งานในข้อสอบ
Block Volume Blocks iSCSI / Paravirtualized เครื่องเดียว (หรือ Read-only share) OS Boot disk, ฐานข้อมูล Oracle/SQL Server ต้องการ IOPS สูง
File Storage (FSS) Files (Folders/Files) NFS v3 ✔ แชร์หลายพันเครื่องพร้อมกัน แชร์โฟลเดอร์สำหรับ Web Cluster, Content Management, Big Data
Object Storage (Standard) Objects (Buckets) HTTP/HTTPS (REST API) ✔ เข้าถึงผ่านอินเทอร์เน็ต เก็บภาพ เสียง วิดีโอ บันทึก Log ข้อมูล Big Data ขนาดมหึมา
Archive Storage Objects (Cold Data) HTTP/HTTPS (ต้อง Restore ก่อน) ✔ เข้าถึงผ่านอินเทอร์เน็ต เก็บสำรองข้อมูลตามกฎหมายระยะยาว (Log เก่า) ไม่ค่อยได้เปิดอ่าน
⚠️ Exam Trap: Archive Storage ไม่สามารถดาวน์โหลดได้ทันที!
ข้อสอบชอบหลอกว่า "ต้องการดาวน์โหลดไฟล์จาก Archive Storage ทันทีเพื่อแก้ปัญหาด่วน" → ทำไม่ได้ทันที! จะต้องสั่ง Restore (Thaw) ก่อน ซึ่งใช้เวลาหลายชั่วโมง หากต้องการเข้าถึงแบบทันทีทันใดแต่เข้าไม่บ่อย ให้เลือก Infrequent Access Tier
▶ 2.4 Database Services (Autonomous DB, Exadata, MySQL HeatWave, NoSQL)
Autonomous Database (ADB)

ฐานข้อมูลอัจฉริยะที่ดูแลตัวเองด้วย Machine Learning: Self-driving (ปรับจูนอัตโนมัติ), Self-securing (ลงแพตช์ความปลอดภัยขณะระบบทำงาน), Self-repairing (กู้คืนตัวเอง)

Exam Keyword: Self-driving, Self-securing, Self-repairing, Auto-patching with zero downtime
ATP vs ADW

ATP (Autonomous Transaction Processing): เหมาะกับงาน Transaction ประจำวัน (OLTP, eCommerce) | ADW (Autonomous Data Warehouse): เหมาะกับงานวิเคราะห์ข้อมูลขนาดใหญ่ (BI, Analytics)

Exam Keyword: ATP = OLTP / high concurrency, ADW = Analytical queries / Data lake
Exadata Database Service

รัน Oracle Database บนโครงสร้างฮาร์ดแวร์ Exadata ที่สร้างขึ้นเพื่อฐานข้อมูลออราเคิลโดยเฉพาะ ความเร็วและ I/O สูงสุด รองรับ RAC

Exam Keyword: Highest performance, Dedicated Exadata hardware, Enterprise OLTP/DW
MySQL HeatWave

ฐานข้อมูล MySQL ที่รวม In-memory Query Accelerator รันงานทั้งธุรกรรม (OLTP) และการวิเคราะห์ (OLAP) ได้ในระบบเดียวกันโดยไม่ต้องแปลง ETL

Exam Keyword: In-memory accelerator, Single database for OLTP and OLAP, No ETL needed
NoSQL Database Cloud

บริการฐานข้อมูล NoSQL แบบ Serverless รองรับการอ่านเขียนด้วยความเร็วระดับไม่กี่มิลลิวินาที (Single-digit millisecond latency)

Exam Keyword: Document/KV store, Low predictable latency, Serverless NoSQL
▶ 2.5 Observability & Management (Monitoring, Logging, Events, Notifications)
OCI Monitoring

เก็บรวบรวมค่าตัววัดทางสถิติ (Metrics) ของระบบ เช่น อัตราการใช้ CPU, การใช้งาน Network และสามารถตั้ง Alarms แจ้งเตือนเมื่อค่าเกินเกณฑ์ที่กำหนด

Exam Keyword: Numeric metric data, Alarms on threshold breached
OCI Logging

ศูนย์กลางจัดการบันทึกข้อความ Log แบ่งเป็น 3 ประเภท: Audit Logs (ประวัติ API), Service Logs (บันทึกจากบริการ OCI), Custom Logs (บันทึกจากแอปในเครื่อง)

Exam Keyword: Centralized log repository, Audit logs, Service logs
OCI Notifications (ONS)

บริการกระจายข่าวสารแบบ Publish/Subscribe ส่งข้อความไปยังปลายทางต่างๆ เช่น Email, Slack, PagerDuty, SMS หรือยิงต่อไปยัง Webhook / OCI Functions

Exam Keyword: Pub/Sub messaging, Push notifications to Email/Slack/Functions
OCI Events

ติดตามการเปลี่ยนแปลงสถานะของทรัพยากร OCI (ตามมาตรฐาน CloudEvents) เช่น มีการอัปโหลดไฟล์ใส่ Bucket → สั่งให้ ONS แจ้งเตือน หรือเรียก Functions ทำงานทันที

Exam Keyword: CloudEvents standard, State changes triggering automated actions

3. OCI Security Architecture

▶ 3.1 Shared Responsibility Model (โมเดลความรับผิดชอบร่วม)

หลักการพื้นฐานที่สุดของความปลอดภัยบนคลาวด์คือ Security OF the Cloud (Oracle รับผิดชอบ) ปะทะกับ Security IN the Cloud (ลูกค้ารับผิดชอบ)

ขอบเขตหน้าที่ (Layer) Oracle Responsibility (Security OF Cloud) Customer Responsibility (Security IN Cloud)
ความปลอดภัยทางกายภาพ (Physical) ✔ อาคาร Data Center, รปภ., วงจรปิด, ไฟฟ้า, แอร์ ✘ ลูกค้าไม่มีหน้าที่เข้าถึงห้องเครื่อง
ฮาร์ดแวร์และโครงข่าย (Hardware & Network) ✔ แม่ข่ายกายภาพ, สวิตช์, สายไฟเบอร์, Hypervisor ✘ Oracle เป็นผู้ดูแลซ่อมแซม
ระบบปฏิบัติการ (OS on IaaS) ✘ Oracle เตรียม Image ให้ ✔ ลูกค้าต้องลง OS Security Patches เอง
ข้อมูลและการเข้าถึง (Data & IAM) ✘ Oracle เข้ารหัส Storage ให้ตามค่าเริ่มต้น ✔ ลูกค้าดูแลข้อมูล นโยบาย IAM การตั้งรหัสผ่าน MFA
เครือข่ายเสมือน (VCN & Firewalls) ✘ จัดเตรียมระบบ SDN ให้ ✔ ลูกค้าตั้งค่า Security Lists, NSGs, Route Tables
▶ 3.2 IAM, Identity Domains, Dynamic Groups & Policy Hierarchy
Identity Domains

ระบบจัดการอัตลักษณ์รูปแบบใหม่บน OCI ที่รวมฟีเจอร์ User/Group Management, Single Sign-On (SSO), MFA และ Identity Governance ไว้ด้วยกัน

Exam Keyword: OCI IAM with Identity Domains, Modern IAM architecture
Dynamic Groups

กลุ่มที่สมาชิกไม่ใช่คน แต่เป็น Compute Instances ที่ตรงตามเงื่อนไข (Matching Rule) เช่น เครื่อง VM ทั้งหมดใน Compartment หนึ่งๆ

Exam Keyword: Group of compute instances, Matching rules
Instance Principals

ฟีเจอร์ที่อนุญาตให้โค้ดที่รันอยู่บน Compute VM สามารถเรียกใช้งาน OCI API ได้โดยตรง โดยไม่ต้องเก็บ Username/Password หรือ API Key ไว้ในโค้ด

Exam Keyword: Authorize VM to call APIs, No credentials stored on instance

โครงสร้างไวยากรณ์ OCI Policy (ออกข้อสอบตรงๆ 1-2 ข้อ)

Allow <subject> to <verb> <resource-type> in <location> [where <conditions>]

ตัวอย่าง: Allow group NetworkAdmins to manage virtual-network-family in compartment Production

ลำดับระดับสิทธิ์ของ Verb (จากน้อยที่สุด → มากที่สุด)

Verb ระดับสิทธิ์ (Permission Level) ความสามารถ (Capabilities) ข้อสอบหลอก
inspect ต่ำสุด (Least privilege) ดูรายชื่อทรัพยากรได้ (List) แต่มองไม่เห็น Metadata หรือข้อมูลจริง ไม่สามารถอ่านไฟล์หรือเปิดดูเนื้อหาได้
read ระดับอ่าน รวมสิทธิ์ inspect + ดู Metadata ของทรัพยากร และอ่านข้อมูลข้างในได้ ไม่สามารถแก้ไข หรือใช้งานทรัพยากรได้
use ระดับใช้งาน รวมสิทธิ์ read + อัปเดต แก้ไข ทำงานกับทรัพยากรที่มีอยู่แล้วได้ สร้างใหม่ (Create) หรือ ลบทิ้ง (Delete) ไม่ได้ (ยกเว้นทรัพยากรชั่วคราวบางชนิด)
manage สูงสุด (Full Control) รวมสิทธิ์ทั้งหมด: สร้าง (Create), ลบ (Delete), แก้ไข, ย้าย, ปรับสิทธิ์ เทียบเท่า Administrator ของบริการนั้นๆ
▶ 3.3 OCI Security Services (Cloud Guard, Security Zones, Vault, Bastion, Data Safe)
Cloud Guard

เครื่องมือตรวจจับความเสี่ยงและพฤติกรรมผิดปกติทั่วทั้ง Tenancy อัตโนมัติ (Detector Recipes) และสามารถแก้ไขปัญหาให้เองได้ทันที (Responder Recipes)

Exam Keyword: Security posture management, Detect and remediate misconfigurations
Security Zones

พื้นที่ Compartment พิเศษที่บังคับใช้นโยบายความปลอดภัยสูงสุดแบบเข้มงวด ปฏิเสธการสร้างทรัพยากรที่ไม่ปลอดภัยตั้งแต่ต้น (เช่น สั่งห้ามไม่ให้เปิด Bucket เป็น Public เด็ดขาด)

Exam Keyword: Strictly enforce security recipes, Prevent bad creation at source
OCI Vault (KMS & Secrets)

บริการจัดการกุญแจเข้ารหัส (Master Encryption Keys) บนฮาร์ดแวร์มาตรฐาน FIPS 140-2 Level 3 HSM และจัดเก็บรหัสผ่าน/Token (Secrets Management)

Exam Keyword: Key Management, Customer-Managed Keys (CMK), Store database secrets
OCI Bastion

เปิดช่องทางเชื่อมต่อ SSH/RDP ไปยัง VM ใน Private Subnet ได้อย่างปลอดภัยแบบชั่วคราว (Time-limited) โดยไม่ต้องมี Public IP และไม่ต้องตั้งเครื่อง Jump Host เอง

Exam Keyword: Secure SSH access to private instances, No public IP needed, No jump host
Oracle Data Safe

ศูนย์กลางความปลอดภัยสำหรับฐานข้อมูลออราเคิล: ค้นหาข้อมูลสำคัญ (Sensitive Data), ทำ Data Masking ซ่อนข้อมูลจริง, ประเมินความเสี่ยง และตรวจสอบผู้ใช้

Exam Keyword: Database security center, Mask sensitive data, User assessment
WAF & Network Firewall

WAF: ป้องกันการโจมตีเว็บเลเยอร์ 7 (SQL Injection, XSS, DDoS) | Network Firewall: Next-Gen Firewall (Palo Alto) กรองข้อมูลระดับ Deep Packet Inspection

Exam Keyword: WAF = Layer 7 web traffic, Network Firewall = Deep packet inspection

ตารางเปรียบเทียบ: Cloud Guard vs Security Zones (ข้อสอบชอบถามแยกความต่าง)

เกณฑ์เปรียบเทียบ Cloud Guard Security Zones
ลักษณะการทำงาน ตรวจจับหลังสร้าง (Detect & Auto-remediate) ป้องกันก่อนสร้าง (Prevent creation upfront)
การตอบสนองเมื่อเกิดความเสี่ยง แจ้งเตือน ปิดสิทธิ์ หรือเรียก Responder Recipe แก้ปัญหา บล็อกคำสั่งทันที (Operation Rejected) ไม่ยอมให้สร้าง
ตัวอย่างการใช้งาน พบว่ามี Bucket ถูกเปิด Public → ส่งแจ้งเตือนและปิด Public ให้อัตโนมัติ ผู้ใช้พยายามสร้าง Bucket แบบ Public → ถูกปฏิเสธทันทีตั้งแต่กดสร้าง
Domain 4 (15-20%)

▶ 4.1 Pricing Models, Universal Credits & Cost Management Tools
Pay As You Go (PAYG)

จ่ายตามจริงที่ใช้งานเป็นรายเดือน ไม่ต้องมีสัญญาผูกมัดหรือจ่ายเงินก้อนล่วงหน้า เหมาะกับเวิร์กโหลดระยะสั้นหรือเริ่มต้นทดสอบระบบ

Exam Keyword: No upfront commitment, Monthly in arrears
Annual Universal Credits (UCC)

ทำสัญญาซื้อเครดิตล่วงหน้าเป็นรายปี ได้ส่วนลดพิเศษตามขนาดสัญญา และสามารถนำเครดิตไปตัดใช้กับบริการ IaaS/PaaS ใดๆ ของ OCI ได้อย่างยืดหยุ่น

Exam Keyword: Annual commitment, Volume discounts, Flexible across services
BYOL (Bring Your Own License)

นำสิทธิการใช้งานซอฟต์แวร์ออราเคิลเดิมที่มีอยู่แล้วในองค์กร (เช่น Oracle Database) มาใช้บน OCI ได้ ทำให้จ่ายค่าบริการคลาวด์ในอัตราพิเศษที่ถูกลงมาก

Exam Keyword: Apply existing on-premises licenses, Lower cloud pricing
OCI Cost Analysis

หน้า Dashboard กราฟิกแสดงการวิเคราะห์ค่าใช้จ่ายย้อนหลัง กรองดูตาม Compartment, บริการ, วันที่ หรือ Cost-Tracking Tags

Exam Keyword: Visual cost visualization, Filter spend by compartment/tags
OCI Budgets

ตั้งเกณฑ์งบประมาณรายจ่ายใน Compartment และส่งอีเมลแจ้งเตือนเมื่อยอดใช้จริงหรือยอดพยากรณ์ล่วงหน้า (Forecasted) เกินเปอร์เซ็นต์ที่กำหนด

Exam Keyword: Set spend thresholds, Alert notifications, Does NOT terminate instances
Usage Reports

ไฟล์สรุปรายละเอียดการใช้งานรายวันในรูปแบบ CSV ละเอียดระดับรายชั่วโมง เก็บไว้ใน Object Storage อัตโนมัติเป็นเวลาหลายเดือน

Exam Keyword: Daily CSV report, Stored in Object Storage, Detailed hourly usage
⚠️ Exam Trap: OCI Budgets ไม่มีวันหยุดการทำงานของเซิร์ฟเวอร์!
จำให้แม่น: ฟังก์ชัน Budgets มีหน้าที่ส่งการแจ้งเตือน (Notifications) ผ่าน Email หรือ ONS เท่านั้น ไม่มีอำนาจในการหยุดเซิร์ฟเวอร์, ลบ Resource หรือขัดขวางการทำงานใดๆ ทั้งสิ้น เมื่อยอดใช้จ่ายแตะ 100%
▶ 4.2 Tagging, Compartment Quotas, Service Limits, SLAs & Resource Manager

ตารางเปรียบเทียบ: Defined Tags vs Free-form Tags

คุณลักษณะ Free-form Tags (แท็กอิสระ) Defined Tags (แท็กแบบมีโครงสร้าง)
โครงสร้างและสคีมา ไม่มีสคีมา เป็น Key-Value ธรรมดา (เช่น env: test) มี Tag Namespace ควบคุมโครงสร้างและประเภทข้อมูล
การควบคุมสิทธิ์ ใครสร้างทรัพยากรก็พิมพ์ใส่เองได้ตามใจชอบ จำกัดสิทธิ์ผู้ดูแลได้ผ่าน IAM Policies
การควบคุมค่าที่กรอก ไม่มีการตรวจสอบ (พิมพ์ผิดหรือซ้ำซ้อนได้ง่าย) ตั้งค่ารายการตัวเลือกที่กำหนดล่วงหน้า (Predefined list) ได้
การคิดบิล (Cost Tracking) ไม่สามารถใช้ทำ Cost-tracking tags ได้ รองรับ Cost-tracking tags สำหรับวิเคราะห์บิลใน Cost Analysis

ตารางเปรียบเทียบ: Service Limits vs Compartment Quotas

รายการ Service Limits (ขีดจำกัดจาก Oracle) Compartment Quotas (โควตาที่ลูกค้าตั้งเอง)
ผู้กำหนด Oracle เป็นผู้กำหนดค่าเริ่มต้นให้กับ Tenancy ผู้ดูแลระบบของลูกค้า (Admin) เป็นผู้เขียน Policy
การปรับเปลี่ยนค่า ต้องส่งคำร้องขอ Service Limit Increase ผ่าน Console Admin แก้ไขข้อความใน Quota Policy ได้ทันที
วัตถุประสงค์ ป้องกันการใช้ทรัพยากรเกินพิกัดของ Data Center ควบคุมและจำกัดการผลาญทรัพยากรของแต่ละทีมใน Compartment
OCI Triple SLA (ครอบคลุม 3 ด้าน)

OCI เป็นผู้ให้บริการคลาวด์รายเดียวที่มีข้อตกลงระดับการให้บริการ (SLA) ครอบคลุมทั้ง 3 มิติ:
1. Availability SLA: การันตีระบบออนไลน์ไม่ล่ม
2. Manageability SLA: การันตีความสามารถในการเรียก API จัดการทรัพยากร
3. Performance SLA: การันตีความเร็วและเสถียรภาพของ I/O และเครือข่าย

Exam Keyword: Availability, Manageability, and Performance SLAs
OCI Resource Manager

บริการจัดการโครงสร้างพื้นฐานในรูปแบบโค้ด (Infrastructure as Code - IaC) ที่พัฒนาขึ้นบน HashiCorp Terraform ในรูปแบบ Fully-managed Service ช่วยจัดการ State File และล็อกการประมวลผลให้อัตโนมัติ

Exam Keyword: Managed Terraform service, State file management, IaC

Exam Traps

⚠️ Top 15 ข้อสอบหลอกบ่อยที่สุด (Common Traps & Pitfalls)

จุดที่คนสอบตกมักเข้าใจผิด
หลอกที่ 1: Budgets สั่งปิดเครื่องเมื่อเงินหมด

ความจริง: OCI Budgets ทำหน้าที่ส่งอีเมล/แจ้งเตือนเตือนเท่านั้น ไม่มีการหยุด ปิด หรือลบทรัพยากรใดๆ ทั้งสิ้น หากต้องการจำกัดไม่ให้สร้างทรัพยากรเพิ่ม ต้องใช้ Compartment Quotas

หลอกที่ 2: Security List บังคับใช้กับระดับ VM

ความจริง: Security List บังคับใช้ที่ระดับ Subnet ทุกเครื่องใน Subnet นั้นต้องรับกฎเดียวกัน ถ้าต้องการกำหนดกฎเฉพาะเจาะจงระดับเครื่อง VM เดี่ยวๆ ต้องใช้ Network Security Group (NSG)

หลอกที่ 3: NAT Gateway ยอมให้คนนอกเชื่อมเข้าหาเซิร์ฟเวอร์

ความจริง: NAT Gateway ให้สิทธิ์การสื่อสาร ขาออกทางเดียวเท่านั้น (Outbound only) ไม่ยอมให้ทราฟฟิกจากอินเทอร์เน็ตภายนอกยิงเข้ามาหาเครื่อง Private Subnet โดยตรง

หลอกที่ 4: Archive Storage ดาวน์โหลดได้ทันที

ความจริง: Archive Storage ต้องสั่ง Restore (หลายชั่วโมง) ก่อนจึงจะเริ่มดาวน์โหลดได้ ถ้าโจทย์บอกว่าต้องการเปิดไฟล์ได้ทันทีโดยไม่เสียเวลารอ ต้องตอบ Standard Tier หรือ Infrequent Access Tier

หลอกที่ 5: Fault Domain ป้องกันน้ำท่วมตึก Data Center

ความจริง: Fault Domain อยู่ภายในห้องเดียวกัน ป้องกันได้แค่ระดับตู้ Rack, สวิตช์ หรือระบบไฟของตู้ หากตึก Data Center ถูกน้ำท่วม ต้องอาศัย Availability Domain (AD) แยกตึก หรือข้าม Region

หลอกที่ 6: Compartment คือ Physical Boundary หรือ Region

ความจริง: Compartment เป็น Logical Boundary (การแบ่งกลุ่มเชิงตรรกะ) มีขอบเขตระดับ Global สมาชิกใน Compartment เดียวกันสามารถอยู่ข้ามหลายๆ Region ทั่วโลกได้

หลอกที่ 7: Service Gateway ยิงข้อมูลออก Public Internet

ความจริง: Service Gateway วิ่งอยู่บน Oracle Private Backbone Network เท่านั้น ไม่แตะต้องเครือข่ายอินเทอร์เน็ตสาธารณะเลย ปลอดภัยสูงมาก

หลอกที่ 8: Verb "use" สามารถสร้างและลบ Resource ได้

ความจริง: Verb use อนุญาตแค่ใช้งานและแก้ไขค่าคอนฟิกที่มีอยู่แล้ว แต่ ไม่สามารถสร้างใหม่ (Create) หรือลบทิ้ง (Delete) ได้ หากต้องการสร้างหรือลบ ต้องใช้ Verb manage

หลอกที่ 9: FastConnect วิ่งผ่านอินเทอร์เน็ตแบบเข้ารหัส

ความจริง: สิ่งที่วิ่งผ่าน Internet คือ Site-to-Site VPN ส่วน FastConnect คือการลากสายเชื่อมต่อทางกายภาพส่วนตัว (Dedicated Physical Connection) ซึ่งไม่ผ่านอินเทอร์เน็ตเลย

หลอกที่ 10: Pre-Authenticated Request (PAR) ต้องมีบัญชี OCI

ความจริง: PAR ถูกสร้างขึ้นมาเพื่อให้คนภายนอกที่ ไม่มีบัญชี OCI และไม่มี IAM Credentials สามารถดาวน์โหลดหรืออัปโหลดไฟล์ผ่าน URL ชั่วคราวได้

หลอกที่ 11: Free-form Tags บังคับสคีมาได้

ความจริง: Free-form Tags ไม่มีสคีมา ใครพิมพ์อะไรก็ได้ ตรวจสอบความถูกต้องไม่ได้ หากต้องการบังคับสคีมาและทำ Cost-tracking ต้องใช้ Defined Tags ภายใต้ Tag Namespace

หลอกที่ 12: Network Load Balancer (NLB) รองรับการทำ SSL Offloading

ความจริง: NLB ทำงานระดับ Layer 4 แบบ Pass-through ไม่มีฟีเจอร์ถอดรหัส SSL หรือ Path routing หากต้องการ SSL Termination และตรวจสอบ HTTP Header ต้องใช้ Flexible Load Balancer (Layer 7)

หลอกที่ 13: ลูกค้าต้องดูแลความปลอดภัยฮาร์ดแวร์บน IaaS

ความจริง: ใน Shared Responsibility Model ฮาร์ดแวร์กายภาพและศูนย์ข้อมูลเป็นหน้าที่ของ Oracle เสมอ ลูกค้าบน IaaS ดูแลตั้งแต่ระบบปฏิบัติการ (OS Patches), ข้อมูล, และ Network Rules

หลอกที่ 14: Cloud Guard บล็อกไม่ให้ผู้ใช้กดสร้าง Resource ผิดพลาด

ความจริง: เครื่องมือที่บล็อกคำสั่งสร้างตั้งแต่แรกเริ่มคือ Security Zones ส่วน Cloud Guard คือระบบตรวจจับและแจ้งเตือนหรือสั่งแก้ปัญหาหลังจากสร้างไปแล้ว

หลอกที่ 15: OCI SLA การันตีเฉพาะความพร้อมใช้งาน (Availability) เท่านั้น

ความจริง: OCI มี Triple SLA การันตีครบทั้ง 3 ด้าน: Availability (ความพร้อมใช้), Manageability (ความสามารถในการเรียก API), และ Performance (ประสิทธิภาพความเร็ว)

🌙 Last-Night Review: สรุปเข้ม 1 หน้ารวมจุดออกสอบแน่นอน

อ่าน 15 นาทีก่อนนอนในคืนก่อนสอบ
  • 1 Region = พื้นที่ภูมิศาสตร์ | 1 AD = 1 Data Center อิสระ | 1 AD มี 3 Fault Domains เสมอ (Anti-affinity ป้องกัน Hardware Failure)
  • Compartment = หน่วยจัดกลุ่มทรัพยากรเชิงตรรกะ (Logical Boundary), ซ้อนได้สูงสุด 6 ระดับ, ขอบเขตระดับ Global Scope ข้าม Region ได้
  • Dedicated Region = ยกคลาวด์ OCI ไปวางที่บ้านลูกค้า | Alloy = พาร์ตเนอร์สร้างคลาวด์แบรนด์ตนเอง | Multicloud = ต่อ Oracle DB ข้ามคลาวด์ Low latency
  • Bare Metal = ไม่มี Hypervisor, คุมฮาร์ดแวร์ 100%, ประสิทธิภาพสูงสุด | VM = รันบน Hypervisor คุ้มค่าเงิน
  • Flexible Shapes = กำหนด OCPU และ RAM เองได้ตามต้องการ เพื่อประหยัดต้นทุน
  • OKE = จัดการ Kubernetes Cluster ฟรี Master Node | OCI Functions = Serverless รันโค้ดตอบสนอง Event บนมาตรฐาน Fn Project
  • Internet Gateway = เน็ตเข้า-ออก 2 ทาง (Public Subnet) | NAT Gateway = ออกเน็ตทางเดียวเพื่อ Patch (Private Subnet)
  • Service Gateway = เข้าถึง Object Storage/ADB ผ่านเน็ตส่วนตัว Oracle ไม่แตะ Internet | DRG = เชื่อม VPN / FastConnect / Peering
  • FastConnect = ลากสายตรงส่วนตัวความเร็วสูง ไม่ผ่านเน็ต | Site-to-Site VPN = อุโมงค์ IPSec วิ่งบน Public Internet
  • Security List = กรองข้อมูลระดับ Subnet | Network Security Group (NSG) = กรองข้อมูลระดับ VNIC/เครื่อง
  • Load Balancer (L7) = HTTP/HTTPS, SSL Offloading, Path Routing | Network Load Balancer (L4) = Ultra-low latency, Pass-through
  • Block Volume = NVMe SSD สำหรับ Boot disk / ฐานข้อมูล | File Storage (FSS) = NFS v3 แชร์ไฟล์ข้ามหลายพันเครื่องพร้อมกัน
  • Object Storage = ข้อมูล Unstructured ผ่าน HTTP REST API | Archive Tier = ค่าจัดเก็บถูกสุด ต้อง Restore ก่อนดาวน์โหลดได้
  • Pre-Authenticated Requests (PAR) = ลิงก์ชั่วคราวให้คนนอกเข้าถึงไฟล์ใน Bucket โดย ไม่ต้องมีบัญชี OCI
  • Autonomous Database (ADB) = Self-driving (จูนเอง), Self-securing (แพตช์เอง), Self-repairing (กู้คืนเอง) มีรุ่น ATP และ ADW
  • MySQL HeatWave = รวมงานธุรกรรม (OLTP) และงานวิเคราะห์ (OLAP) ไว้ใน MySQL เครื่องเดียวโดยไม่ต้องทำ ETL
  • Shared Responsibility Model: Oracle ดูแล Security OF the Cloud (กายภาพ ฮาร์ดแวร์) | ลูกค้าดูแล Security IN the Cloud (ข้อมูล IAM กฎเน็ต OS patches บน IaaS)
  • Instance Principals: ให้สิทธิ์ Compute VM เรียกใช้ OCI APIs ผ่าน Dynamic Group โดยไม่ต้องฝังรหัสผ่านหรือ API Key
  • ลำดับ Policy Verbs: inspect (ดูชื่อ) < read (ดูเนื้อหา) < use (ใช้งานแก้ได้ แต่สร้าง/ลบไม่ได้) < manage (สิทธิ์สูงสุด แอดมินสร้าง-ลบได้)
  • OCI Vault: จัดการกุญแจเข้ารหัส (KMS) บน FIPS 140-2 Level 3 HSM และเก็บ Secrets (รหัสผ่าน/Token)
  • Cloud Guard: ตรวจจับความเสี่ยงหลังสร้าง (Detect & Auto-remediate) | Security Zones: ป้องกันไม่ให้สร้าง Resource ที่ผิดกฎตั้งแต่ต้น (Strictly prevent)
  • OCI Bastion: รีโมต SSH/RDP เข้าเครื่อง Private Subnet ชั่วคราว โดยไม่ต้องมี Public IP และไม่ต้องตั้ง Jump host
  • Budgets: ส่งอีเมลแจ้งเตือนยอดเงินเท่านั้น ไม่เคยสั่งปิดเครื่อง! | Compartment Quotas: นโยบายล็อกไม่ให้สร้างเครื่องเกินจำนวน
  • Defined Tags: มี Tag Namespace กำหนดค่าช้อยส์ได้ รองรับ Cost-tracking | Free-form Tags: ไม่มีสคีมา
  • Triple SLA: การันตี 3 มิติรายเดียวในโลก: Availability + Manageability + Performance

Exam Strategy

💡 กลยุทธ์และเทคนิคการทำข้อสอบ (Exam Strategy)

เทคนิคทำข้อสอบให้ผ่านฉลุยในรอบเดียว
1. บริหารเวลา (Time Management)

ข้อสอบมาตรฐานมีประมาณ 40-50 ข้อ ให้เวลา 60-90 นาที คิดเป็นเฉลี่ย ประมาณ 1.5 นาทีต่อข้อ ห้ามติดหล่มข้อใดข้อนึงเกิน 2 นาที หากไม่มั่นใจให้กาข้อที่น่าจะถูกที่สุดแล้วกด Flag for Review ไว้ก่อน

2. เทคนิคตัดช้อยส์ (Elimination)

ข้อสอบ OCI จะมีช้อยส์ลวงที่ "ไม่มีชื่อบริการนี้อยู่จริงใน OCI" หรือคำศัพท์ที่สลับเอาคลาวด์อื่นมาใส่ (เช่น S3 Bucket แทน Object Storage Bucket, VPC แทน VCN, EC2 แทน Compute) ตัดตัวเลือกพวกนี้ทิ้งก่อนได้ทันที

3. ข้อสอบประเภท "Select TWO" หรือ "Select THREE"

อ่านโจทย์ให้จบเสมอว่าให้เลือกกี่ข้อ! หากโจทย์ระบุว่า Select TWO ตัวเลือกที่ถูกมักจะมาเป็นคู่คำตรงข้าม หรือจับคู่ระหว่างคอนเซปต์ High Availability เช่น AD กับ FD หรือ Security List กับ NSG

4. ระวังคำว่า "NOT" และ "LEAST"

สังเกตคำปฏิเสธ เช่น "Which is NOT a valid feature..." หรือ "Which action requires the LEAST privilege..." หากถาม Least privilege ให้ตัด Verb manage ทิ้งก่อน แล้วมองหา inspect หรือ read
