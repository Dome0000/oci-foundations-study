2.1 Compute และ Cloud Native D2 · 50%

อ่านประมาณ 45–60 นาที · objective 2.1 — "Compute" เป็นส่วนที่น้ำหนักมากสุดของข้อสอบ

Why it matters — ทำไมเรื่องนี้สำคัญ

Compute (บริการคอมพิวต์) คือหัวใจของทุก workload บน cloud เกือบทุกสถาปัตยกรรมต้องเลือก "รันโค้ดที่ไหน" — ข้อสอบถามไม่ได้ว่า EC2 คู่แข่งคืออะไร แต่ถามว่า "สถานการณ์นี้ควรใช้บริการไหน และเพราะอะไร" ถ้าเข้าใจความต่างของ Compute / Container Instances / OKE / Functions คุณจะตัดโจทย์ออกได้ครึ่งหนึ่ง

อุปมา
ลองคิดว่าการรัน workload คือการหารถขับ: Bare Metal = เช่ารถทั้งคันขับเอง (ได้ทั้งคัน ปรับแต่งได้หมด) · VM = เช่าห้องในรถตู้ร่วม (ถูกกว่า ยืดหยุ่น แต่ใช้ร่วมเครื่องกับคนอื่น) · Container Instances / OKE = เรียกเฉพาะตู้คอนเทนเนอร์ไปวาง ไม่ต้องยุ่งกับตัวรถ · Functions = เรียกมอเตอร์ไซค์วิ่งส่งทีละรอบ จ่ายเฉพาะตอนวิ่งจริง

Key concepts — VM vs Bare Metal และ Shapes

Compute มี 2 แบบหลัก

Virtual Machine (VM)Bare Metal (BM)
คืออะไรInstance ที่รันบน hypervisor แบบ multi-tenant (แชร์เครื่องจริงกับ VM อื่น)ทั้งเซิร์ฟเวอร์จริงเครื่องหนึ่งเป็นของคุณเต็ม ๆ ไม่มี hypervisor คั่น
เหมาะกับงานทั่วไป เว็บแอป ไมโครเซอร์วิส ต้นทุนต่ำงานที่ต้องการ performance เต็มที่ / ต้องการเข้าถึง hardware โดยตรง (เช่น low-latency, licensing ที่ผูกกับ socket, workload เบา hypervisor ไม่ได้)
ข้อจำกัดมี overhead ของ hypervisor (เล็กน้อย)แพงกว่า, ได้เครื่องใหญ่เลย, เปลี่ยน shape ทีหลังไม่ได้ (ต้อง terminate + relaunch)
Boot timeเร็ว (นาที)ช้ากว่า VM

Shape = สูตรกำหนดขนาด instance

Shape (รูปแบบขนาด) คือเทมเพลตที่กำหนด OCPU, memory, network bandwidth และจำนวน VNIC 1 OCPU บน x86 (AMD/Intel) = 2 vCPU; บน Ampere A1 = 1 core = 1 vCPU (นี่คือจุดที่ข้อสอบชอบหลอก)

  • Fixed shape — ขนาดตายตัว เช่น VM.Standard.E4.Flex ไม่ใช่ fixed (ตัวนี้เป็น Flex) …ตัวอย่าง fixed เก่า ๆ เช่น VM.Standard2.1, VM.Standard.E2.1.Micro (Always Free: 1 OCPU / 1 GB)
  • Flexible shape (Flex) — เลือกจำนวน OCPU และ memory เองอิสระ (memory ต่อ OCPU สูงสุดตามเอกสารปัจจุบัน; ขั้นต่ำ 1 GB ต่อ OCPU หรือ 1 GB แล้วแต่อะไรมากกว่า) ปรับ scale ภายหลังได้
  • ตระกูล CPU: AMD EPYC (E-series เช่น E4/E5/E6), Intel Xeon (Standard3/Standard4/Optimized3), Ampere Arm (A1/A2/A4 — ราคา/ประสิทธิภาพดี, ไม่รองรับ Windows)
  • GPU shapes: NVIDIA (P100, V100, A100, H100/H200, Blackwell) และ AMD MI300X สำหรับ AI/HPC
  • VM.Standard.E2.1.Micro และ VM.Standard.A1.Flex (บางส่วน) เป็นสิทธิ์ Always Free — ตัวเลขโควตาเปลี่ยนได้เสมอ ตรวจสอบก่อนสอบ

Dedicated VM Host (DVH)

เช่า "เครื่องจริงทั้งเครื่องแบบ dedicated" แต่รันเฉพาะ VM instances ของคุณเอง — ได้ isolation ระดับ hardware (เช่น ข้อกำหนด compliance/licensing) โดยยังได้ความยืดหยุ่นของ VM บนเครื่องนั้น จ่ายตามเครื่อง ไม่ใช่ราย instance

Preemptible Instances (Instance แบบถูกขัดจังหวะได้)

  • ราคาถูกกว่า on-demand มาก เหมาะกับ batch jobs, rendering, CI, fault-tolerant และ stateless workload ที่ทนต่อการถูก terminate ได้
  • Oracle สามารถ reclaim (ยึดคืน) instance ได้ทุกเมื่อเมื่อ capacity ต้องการ — ไม่มีการรับประกัน uptime แบบ SLA ปกติ
  • ถ้า workload คุณทน interrupt ไม่ได้ ห้ามใช้ preemptible

Images และ Boot Volume

  • Platform image — image ทางการของ Oracle (Oracle Linux, Ubuntu, Windows Server, CentOS ฯลฯ) แพตช์และพร้อมใช้
  • Custom image — สร้างจาก instance ของคุณเอง ใช้ clone เครื่องที่ตั้งค่าไว้แล้ว (golden image)
  • Community image — จากชุมชน (ไม่รับประกันจาก Oracle)
  • Boot volume — block volume ที่เก็บ OS ตั้งต้น instance; ลบ instance แล้วเลือก "preserve boot volume" ได้ เพื่อ backup/clone/สร้าง instance ใหม่จาก boot volume เดิม
  • เป็น AD-specific resource (ผูกกับ AD เดียวกับ instance)

Cloud-init และ Instance Configuration

  • cloud-init — กลไกมาตรฐานส่งสคริปต์/คอนฟิกตอน instance บูตครั้งแรก (ติดตั้ง package, เขียนไฟล์, ตั้ง user) — ทำให้ instance พร้อมใช้งานโดยไม่ต้อง SSH เข้าไปตั้งเอง
  • Instance configuration — blueprint ที่เก็บ shape, image, VCN/subnet, SSH key, cloud-init ไว้เป็น template
  • Instance pool — กลุ่ม instance ที่สร้างจาก configuration เดียวกัน (instance เหมือน ๆ กันหลายตัว)

Instance Pools และ Autoscaling

  • Autoscaling configuration — ปรับจำนวน instance ใน pool อัตโนมัติตาม metric (เช่น CPU utilization หรือ custom metric) หรือแบบ schedule (เพิ่มตอนกลางวัน ลดตอนกลางคืน)
  • Capacity type: capacity reserved / on-demand / preemptible (ตั้งได้ใน pool)
  • Load balancer + instance pool + autoscaling เป็นชุดมาตรฐานสำหรับเว็บที่ทราฟฟิกแกว่ง

การเข้าถึง Instance

วิธีใช้เมื่อไรหมายเหตุ
SSH (port 22) ผ่าน public IP หรือผ่าน Bastionเข้า Linux instance โดยตรงต้องมี subnet เปิดทางและ security list/NSG อนุญาต; ไม่ควรเปิด 22 สาธารณะ — ใช้ Bastion ดีกว่า
Bastion serviceทางเข้าทางการไปยัง private subnet แบบมี audit + จำกัดเวลาไม่ต้องมี jump box เอง; รองรับ SSH และ Windows RDP
Console Connection (serial console แบบ in-band)กรณี instance เข้าไม่ได้ผ่าน network (เช่น firewall ผิด, รหัสผ่านหาย)เข้าผ่าน web console ได้แม้ระบบปฏิบัติการมีปัญหา network
Instance principalsให้ instance เรียก OCI API โดยไม่ต้องฝัง API keyดูรายละเอียดในหน้า IAM

Cloud Native Services บน OCI

Container Instances

รัน container เดี่ยว ๆ แบบ serverless โดยไม่ต้องจัดการเซิร์ฟเวอร์/Kubernetes — เหมาะกับงานสั้น ๆ งาน batch ที่เป็น container หรือ microservice ที่ไม่อยากแบก cluster

Oracle Kubernetes Engine (OKE)

Managed Kubernetes — Oracle ดูแล control plane ให้ คุณเลือกชนิด node ได้:

ชนิด nodeใครจัดการเหมาะกับ
Managed nodesOracle สร้าง/แพตช์ node ให้จาก node pool image ทางการงานทั่วไป งาน production ส่วนใหญ่
Virtual nodesserverless pods — ไม่เห็น VM เลย Oracle จัดการทุกอย่างไม่อยากดูแล node เลย, isolation ต่อ pod, จ่ายตาม pod
Self-managed nodesคุณเอา VM ของตัวเองมา join clusterต้องการ customization เต็มที่ (image พิเศษ, hardware เฉพาะ)

OCIR (Oracle Cloud Infrastructure Registry)

Container registry ส่วนตัวสำหรับเก็บ image (Docker/OCI image) ใช้ร่วมกับ OKE / Container Instances; รองรับทั้ง private/public repository

Functions (Oracle Functions)

บริการ serverless Functions as-a-Service บนพื้นฐาน Fn Project — deploy ฟังก์ชันแล้ว OCI ขยายจำนวนรันให้อัตโนมัติตาม event; จ่ายเฉพาะตอน execute; เหมาะกับ event handler, glue code, API เล็ก ๆ

API Gateway

ให้ HTTPS endpoint เดียวสำหรับรวมหลาย backend (Functions, HTTP services) — ทำ auth, rate limiting, request transformation ได้โดยไม่ต้องเขียนโค้ดเอง

Events และ Notifications

  • Events — event-driven: เมื่อมีเหตุการณ์ใน OCI (เช่น bucket ถูกเขียน object, instance หยุด) trigger action ไปยัง Functions / Streaming / Notifications ได้
  • Notifications — ส่งข้อความไปยัง subscribers (email, SMS, HTTPS endpoint, Slack, PagerDuty ฯลฯ) ผ่าน topic

Streaming

Managed Kafka-compatible streaming platform สำหรับ high-volume telemetry/clickstream — แทนการรัน Kafka เอง

Resource Manager

บริการ managed Terraform — เก็บ stack (template) และ state ไว้ใน OCI, กด apply จาก Console ได้, จัดการ drift และทำซ้ำหลาย environment ได้ง่าย เหมาะกับ infrastructure-as-code โดยไม่ต้องติดตั้ง terraform เอง

DevOps

บริการ CI/CD ครบวงจร: build pipelines, deploy pipelines (rolling, blue-green, canary), เชื่อมกับ OKE / Compute ได้ตรง

ตารางตัดสินใจ — ควรใช้อะไรเมื่อไร

สถานการณ์คำตอบที่น่าจะเป็น
แอป legacy ที่ต้องการ Windows หรือ software ผูกกับ OS/socket licensingCompute (VM หรือ Dedicated VM Host)

รัน container งานสั้น ๆ ไม่อยากมี clusterContainer Instances

ไม่อยากดูแล node เลยสักตัว, จ่ายตาม podOKE Virtual Nodes
อยากได้ Kubernetes แต่ต้องใช้ image/kernel พิเศษOKE Self-managed nodes

Exam Focus — สิ่งที่ข้อสอบชอบถาม

ข้อสอบชอบถาม
  • 1 OCPU = กี่ vCPU? → x86 = 2 vCPU, Arm A1 = 1 thread/core ต่อ OCPU (Arm A2/A4 = 2 cores ต่อ OCPU)
  • Flex shapes: เลือก OCPU และ memory เองได้ — เทียบกับ fixed shapes
  • Workload ทน interrupt ได้ → preemptible; ห้ามใช้กับงาน critical
  • ต้องการ hardware isolation แบบ managed → Dedicated VM Host; ต้องการเครื่องทั้งเครื่อง → Bare Metal
  • instance เข้าไม่ได้แม้แต่ SSH → Console Connection (in-band serial)
  • รัน container ไม่มี cluster → Container Instances; ต้องการ orchestration → OKE
  • OKE node แบบไหนที่ Oracle ดูแล OS ให้ → Managed nodes; pod แบบ serverless → Virtual nodes
  • Terraform แบบ managed ใน OCI → Resource Manager
  • Boot volume เป็น AD-specific — ย้าย instance ข้าม AD ต้องผ่าน image/backup

Common Traps — จุดที่คนมักตอบผิด

กับดัก
  • "Preemptible = cheaper SLA" — ผิด: preemptible คือ capacity ที่ Oracle reclaim ได้ทุกเมื่อ ไม่มี SLA ไม่ใช่แค่ราคาถูก
  • "Dedicated VM Host = Bare Metal" — ผิด: DVH รัน VM หลายตัวของคุณบนเครื่อง dedicated (ยังมี hypervisor); Bare Metal ไม่มี hypervisor เลย
  • "OKE Virtual nodes = VM ที่เล็กลง" — ผิด: virtual nodes คือ serverless pods; คุณไม่เห็นและไม่ต้องดูแล node ใด ๆ
  • "Container Instances เหมาะกับ production ที่ scale หลายร้อย pod" — ควรเป็น OKE ถ้าต้องการ orchestration, service discovery, rolling deploy เต็มรูปแบบ
  • "Boot volume backup ย้ายไป region อื่นได้ตรง ๆ" — ไม่ได้โดยตรง: ใช้ custom image (ข้าม region ผ่าน image copy) หรือ block volume backup cross-region replication
  • "Arm shapes รัน Windows ได้" — ไม่ได้ ทั้ง A1/A4 ไม่รองรับ Windows
  • "Autoscaling = เพิ่ม VM เรื่อย ๆ" — autoscaling ปรับ เข้าและออก ตาม policy (CPU, schedule, custom metrics)

Scenario — โจทย์สถานการณ์

Scenario 1
บริษัทมี batch job แปลงภาพทุกคืน ทนการถูกหยุดกลางคันได้ และอยากลดต้นทุนให้มากที่สุด ควรใช้บริการใด?
วิธีคิด: คีย์เวิร์ด "ทน interrupt ได้ + ลดต้นทุน" → Preemptible instances (หรือ instance pool แบบ preemptible + autoscaling) ไม่ใช่ Bare Metal ไม่ใช่ on-demand VM ปกติ
Scenario 2
ทีม dev มี microservices 12 ตัว ต้องการ rolling update, service discovery และ auto-scaling แต่ไม่อยากดูแล control plane ของ Kubernetes ควรเลือกอะไร?
วิธีคิด: คีย์เวิร์ด "microservices + orchestration + ไม่อยากดูแล control plane" → OKE (Oracle ดูแล control plane ให้) ส่วน node เลือก Managed nodes ถ้าอยากให้ Oracle แพตช์ node ด้วย — ถ้าไม่อยากดู node เลยเลือก Virtual nodes

Check yourself

2 vCPU — OCPU คือ physical core ของ AMD/Intel; 1 core = 2 threads (vCPU) จึงนับเป็น 2 vCPU ส่วน Ampere A1 นับ 1 OCPU = 1 core = 1 vCPU
OKE Managed nodes — Oracle สร้างและแพตช์ node จาก image ทางการให้ ต่างจาก Self-managed ที่คุณดูแลเอง และ Virtual nodes ที่ไม่มี node ให้เห็นเลย
Console Connection — การเชื่อมต่อแบบ serial in-band ผ่าน Console โดยไม่ต้องพึ่ง network ของ instance
Resource Manager — managed Terraform บน OCI เก็บ stack และ state ไว้ ทำงานจาก Console/CLI ได้เลย
VCN เป็น regional resource (ครอบคลุมทุก AD ในภูมิภาค) ส่วน boot volume และ compute instance เป็น AD-specific
