2.2 Networking D2 · 50%

อ่านประมาณ 60–75 นาที · objective 2.2 — หัวข้อที่ข้อสอบถามลึกและถี่ที่สุดเรื่องหนึ่ง

Why it matters

ทุก instance, database และโหลดงานที่คุณรัน ล้วนอยู่ในเครือข่าย — ถ้าเครือข่ายออกแบบผิด แอปจะเข้าไม่ถึงหรือเปิดเกินจำเป็น (เสี่ยงความปลอดภัย) ข้อสอบถามลักษณะ "traffic จาก A ไป B ต้องผ่านอะไรบ้าง" เสมอ

อุปมา
VCN = อาคารสำนักงานของคุณ · subnet = ห้องแต่ละห้อง (ห้องรับแขก = public subnet, ห้องเก็บเอกสาร = private subnet) · route table = ป้ายบอกทาง · gateway = ประตูแต่ละประเภท (ประตูหน้าตึก = Internet Gateway, ประตูที่ให้ออกไปซื้อของข้างนอกแต่ไม่ให้ใครเข้ามา = NAT Gateway, ประตูพิเศษไปคลังสินค้าของ Oracle = Service Gateway) · Security List/NSG = รปภ. ตรวจก่อนเข้าห้อง

VCN และ Subnets

  • Virtual Cloud Network (VCN) — เครือข่ายส่วนตัวแบบ customizable ของคุณ ใน Compartment หนึ่งเดียว เป็น regional resource (ครอบคลุมทุก AD ใน region เดียว)
  • IPv4 CIDR ของ VCN อยู่ในช่วง /16 ถึง /30 (เช่น 10.0.0.0/16) เลือกขนาดให้พอใช้; IPv6 รองรับแยก (โดยทั่วไป /56 สำหรับ VCN)
  • หนึ่ง region มีได้หลาย VCN (ค่า default limit มักอ้างถึง 5 — เปลี่ยนได้ ตรวจ Service Limits)
  • Subnet เป็นส่วนย่อยของ VCN CIDR ห้ามซ้อนกัน:
    • Public subnet — subnet ที่ route table ชี้ 0.0.0.0/0 ไป Internet Gateway (ไม่ใช่ checkbox แยกต่างหาก)
    • Private subnet — ไม่มี route ออก IGW; ขาออกใช้ NAT/Service Gateway
    • Regional subnet — ครอบคลุมทุก AD (Oracle แนะนำให้ใช้แบบนี้)
    • AD-specific subnet — ผูกกับ AD เดียว (แบบเก่า, ยังใช้ได้)
  • แต่ละ subnet ผูกกับ route table และ security list หนึ่งตัวขึ้นไป (ระบุได้หลายตัว แต่ rule จะรวมกัน)
  • แต่ละ VCN มี default route table / default security list / default DHCP options มาให้ตั้งแต่สร้าง

Gateways — ใครทำอะไรได้บ้าง

Gatewayทิศทางใช้กับ
Internet Gateway (IGW)เข้า–ออก สองทางpublic subnet ที่ต้องการติดต่ออินเทอร์เน็ตโดยตรง ( instance ต้องมี public IP ด้วย )
NAT Gatewayออกได้อย่างเดียว (outbound-only)private subnet ต้องการออกอินเทอร์เน็ต (เช่น โหลด package) แต่ไม่อนุญาตการเชื่อมต่อขาเข้าจากอินเทอร์เน็ต
Service Gateway (SGW)เข้าถึง Oracle Services จาก VCN โดยไม่ผ่านอินเทอร์เน็ตprivate subnet เรียก Object Storage / OCI services อื่นผ่าน Oracle backbone — ไม่ต้องมี public IP, ไม่ต้องผ่าน NAT
Dynamic Routing Gateway (DRG)เข้า–ออก (เครือข่ายส่วนตัว)Site-to-Site VPN, FastConnect, remote VCN peering, เชื่อมหลาย VCN แบบ hub-and-spoke
Local Peering Gateway (LPG)เข้า–ออก ภายใน region เดียวเชื่อม 2 VCN ใน region เดียวกัน (CIDR ห้ามซ้อน)

Route Tables

  • ทุก subnet ต้องผูก route table (ถ้าไม่ระบุ ใช้ default ของ VCN)
  • การเลือก route ใช้ longest prefix match (เฉพาะเจาะจงที่สุดชนะ) — 10.0.0.0/8 ชนะ 0.0.0.0/0 สำหรับปลายทางในช่วงนั้น
  • ตัวอย่าง route มาตรฐาน: 
    0.0.0.0/0            → Internet Gateway     (public subnet)
0.0.0.0/0            → NAT Gateway          (private subnet ออกอินเทอร์เน็ต)
OCI Services CIDR    → Service Gateway      (private → Object Storage)
on-premises CIDR     → DRG                  (private → datacenter)
VCN อื่น CIDR        → LPG                  (local peering)
  • route เปลี่ยนแล้วมีผลกับ instance ใหม่-เก่าทันที (ไม่ต้อง reboot)

Security Lists vs Network Security Groups (NSG)

Security ListNetwork Security Group (NSG)
ขอบเขตใช้ระดับ subnet (ทุก VNIC/instance ใน subnet ถูกบังคับ)ระดับ VNIC (เลือกเฉพาะ instance ที่ต้องการ, ข้าม subnet ใน VCN เดียวกันได้)
Stateful/Statelessค่า default stateful (return traffic อนุญาตอัตโนมัติ); กำหนด stateless ได้ต่อ ruleค่า default stateful เช่นกัน; กำหนด stateless ได้ต่อ rule
เหมาะกับbaseline กว้าง ๆ ของ subnet (เช่น อนุญาต 22 จาก Bastion เท่านั้น)least-privilege ต่อ tier/แอป (เช่น อนุญาต 8080 จาก NSG ของ web เท่านั้น)
จำนวนต่อ subnetแนบได้หลาย security list (rule รวมกัน)VNIC หนึ่งอยู่ได้หลาย NSG (rule รวมกัน)
หลักจำ
Security List ถามว่า "ห้องนี้ทุกคนเข้าได้ไหม" · NSG ถามว่า "คนกลุ่มนี้เข้าได้ไหม" — มักใช้คู่กัน: security list วาง baseline, NSG วางกฎเฉพาะแอป

Load Balancer (L7) vs Network Load Balancer (L3/L4)

Load BalancerNetwork Load Balancer (NLB)
LayerL7 (HTTP/HTTPS) — รู้จัก path, header, cookieL3/L4 (TCP/UDP/ICMP) — ไม่ parse payload, latency ต่ำมาก
เหมาะกับเว็บ/API ที่ต้อง path-based routing, SSL termination, WAF แนบได้งานที่ต้องการ ultra-low latency หรือ protocol ที่ไม่ใช่ HTTP (เช่น game, DNS, syslog) หรือ throughput สูง
Health checkHTTP path ได้ (เช่น /health)TCP/UDP level
SSLterminate ที่ LB ได้ไม่ terminate (ส่งผ่านอย่างเดียว)
Public/Privateเลือกได้ทั้งสองแบบเลือกได้ทั้งสองแบบ

Peering และ DNS

  • Local peering — 2 VCN ใน region เดียวกัน เชื่อมผ่าน LPG; CIDR ห้ามซ้อน; traffic วิ่งบน backbone ของ Oracle
  • Remote peering — VCN ข้าม region เชื่อมผ่าน DRG ทั้งสองฝั่ง
  • Peering ไม่ transitive — A↔B และ B↔C ไม่ได้แปลว่า A↔C
  • VCN DNS — ชื่อ instance-name.subnet-name.vcn-name.oraclevcn.com resolve ได้ภายใน VCN (DHCP options ควบคุม DNS server)
  • OCI DNS — authoritative DNS hosting + Traffic Management (steering policies: failover, geolocation, latency-based) สำหรับ global traffic routing

FastConnect vs Site-to-Site VPN

FastConnectSite-to-Site VPN
ชนิดวงจรส่วนตัว dedicated (direct / via partner)IPsec tunnel ผ่านอินเทอร์เน็ตสาธารณะ
แบนด์วิดท์สูงมาก (ระดับ Gbps), latency ต่ำ เสถียรจำกัดตาม tunnel, latency ขึ้นกับอินเทอร์เน็ต
การตั้งใช้เวลา provisioning (ผู้ให้บริการ/partner), ค่าใช้จ่ายวงจรตั้งได้เร็ว ใช้แค่ VPN customer-premises equipment (CPE) + OCI DRG
เหมาะกับproduction ใหญ่ ๆ, ข้อมูลเยอะ, ต้องการ SLA เครือข่ายเริ่มต้นเร็ว, backup ของ FastConnect, site เล็ก

Public IP (Ephemeral / Reserved) และ VNIC

  • Ephemeral public IP — ผูกกับ instance/resource ชั่วคราว หายไปเมื่อ terminate หรือถอดออก
  • Reserved public IP — จองแบบ persistent เข้า/ออก instance ไหนก็ได้, เป็น regional resource
  • VNIC — virtual network interface card: instance ทุกตัวมี primary VNIC + เลือก subnet ได้ กำหนด private IP, NSG, source/dest check (ปิดเมื่อทำ router/NAT VM)
  • instance หนึ่งแนบ secondary VNIC ได้หลายใบ (จำนวนตาม shape) แต่ละใบอยู่คนละ subnet ได้ — ใช้ทำ network appliance

VCN Flow Logs และ Network Firewall

  • Flow logs — บันทึก metadata ของทราฟฟิก (ไม่ใช่ payload) ที่เข้า/ออก VNIC ไปยัง Logging service — ใช้ตรวจสอบ, troubleshoot, security audit
  • Network Firewall — managed stateful firewall แบบ next-generation ทำ IDS/IPS และ TLS inspection ได้ วางเป็นจุดตรวจทราฟฟิกของ subnet/VCN (ต่างจาก security list/NSG ที่เป็นแค่ rule allow/deny)

Exam Focus

ข้อสอบชอบถาม
  • "private subnet ต้องออกอินเทอร์เน็ตได้ แต่อินเทอร์เน็ตเข้ามาไม่ได้" → NAT Gateway
  • "private subnet ต้องอ่าน/เขียน Object Storage โดยไม่ผ่านอินเทอร์เน็ต" → Service Gateway
  • "เชื่อม on-premises กับ OCI แบบ dedicated แบนด์วิดท์สูง" → FastConnect; "เร็วและถูก/สำรอง" → Site-to-Site VPN
  • "อนุญาตเฉพาะบาง instance ในหลาย subnet" → NSG; "กฎเดียวทั้ง subnet" → Security List
  • "ต้องรับ HTTP path-based routing" → Load Balancer; "UDP, ultra-low latency" → NLB
  • "ชื่อโดเมนที่ resolve ได้เฉพาะใน VCN" → VCN DNS / DHCP options ไม่ใช่ OCI DNS สาธารณะ
  • Reserved public IP = regional; ephemeral public IP = ผูกกับ resource และหายเมื่อถอด
  • VCN เป็น regional; subnet เป็นได้ทั้ง regional และ AD-specific

Common Traps

กับดัก
  • "public subnet = instance เข้าจากเน็ตได้ทุกตัว" — ไม่: instance ต้องมี public IP ด้วย และ security rules ต้องอนุญาต
  • "Security list stateless ต้องเปิด 2 ทาง" — ใช่: stateful เปิดครั้งเดียว return อนุญาตให้เลย; stateless ต้องเปิดทั้ง ingress และ egress เอง
  • "Peering transitive" — ผิด: A↔B↔C ไม่ได้ทำให้ A↔C คุยกันได้
  • "NAT Gateway เป็นสองทาง" — ผิด: outbound-only; การเชื่อมต่อที่เริ่มจากอินเทอร์เน็ตเข้ามาไม่ได้
  • "Service Gateway คือ VPN ไป on-prem" — ผิด: SGW คือทางไป Oracle Services Network (เช่น Object Storage) เท่านั้น ไม่ใช่ไป on-prem (นั่นคือ DRG)
  • "Load Balancer รองรับ UDP" — ไม่: UDP ต้อง NLB (L3/L4)
  • "DRG ใช้ peer VCN ใน region เดียว" — ใช้ได้แต่ overkill; region เดียวใช้ LPG ง่ายกว่า; DRG ใช้สำหรับ remote peering / VPN / FastConnect

Scenario

Scenario 1
ทีมวาง DB ใน private subnet ต้อง backup ขึ้น Object Storage ทุกคืน โดยห้ามออกอินเทอร์เน็ตสาธารณะเลย ต้องตั้งค่าอะไร?
วิธีคิด: ปลายทาง = Oracle Services Network → สร้าง Service Gateway + route OCI Services CIDR → SGW ใน route table ของ private subnet — ไม่ต้องมี NAT ไม่ต้องมี public IP และข้อมูลไม่ผ่านอินเทอร์เน็ต
Scenario 2
ต้องการเปิดเว็บให้ลูกค้าเข้า โดยให้เฉพาะพอร์ต 443 เข้าถึงได้ และอยาก terminate TLS พร้อมเลือก backend ตาม path (/api ไปเซิร์ฟเวอร์ชุดหนึ่ง, /static ไปอีกชุด) ใช้อะไร?
วิธีคิด: ต้องการ L7 + path routing + TLS termination → Load Balancer (public) หน้า instance ใน private subnet ผ่าน NSG ที่อนุญาตเฉพาะพอร์ตจาก LB

Check yourself

Region — VCN ครอบคลุมทุก Availability Domain ใน region เดียว ใช้ข้าม region ไม่ได้
NAT Gateway + route 0.0.0.0/0 → NAT ใน route table ของ subnet นั้น
Security List บังคับทุก VNIC ใน subnet; NSG เลือกเฉพาะ VNIC ที่ติด tag/อยู่ในกลุ่มได้ ข้าม subnet ใน VCN เดียวกันได้ เหมาะกับ least privilege
Network Load Balancer (L3/L4) — Load Balancer (L7) รองรับเฉพาะ HTTP/HTTPS/TCP/SSL ที่ terminate ไม่ใช่ UDP
Service Gateway (SGW) — ทางพิเศษไป Oracle Services Network บน backbone ของ Oracle
